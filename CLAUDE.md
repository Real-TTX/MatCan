# DesignThix: notes for working in this repository

An **offline Canva**, first a design tool (labels, cards, flyers, posters, social media posts: start from a format tile or one of ten templates, draw in the designer, download or print) and
second, as an add-on ("Zusatz: Serien"), a tool that fills a design from **data lists** through placeholders (`{{Name}}`), so one design prints many labels (mail merge). **`docs/PLAN-CANVA.md` is plan 2** (what "like Canva" means,
document schema 2, phases K1 to K6) and wins over `docs/PLAN.md` where they differ; `docs/EDITOR.md` describes the editor (K3/K4). ASP.NET Core 10 Razor Pages, EF Core 10 on PostgreSQL 17, one container (port **3043**)
plus a database. User-facing text is **German** ("du"); code, comments and docs (except the README) are English. The infrastructure (setup, sign-in, TOTP,
sessions, list controls, shell, AI layer, PWA, Docker, CI) was ported from `../MatTicket`; the look is MatDesign (`../MatDesign`, MatUi copied into
`src/DesignThix/wwwroot/ui`, version in `scripts/matui-synced.txt`, never edited there). Before changing UI read MatDesign's `CLAUDE.md` and
`docs/ADOPTING.md`. **`docs/PLAN.md` is the build plan (product, document format, architecture); its "Status" section at the top lists where the result differs from it.** Phases A to I (plan 1) and K1 to K6 (plan 2) are done; `docs/PLAN-CANVA.md` has a "Status" section with the deviations. **`docs/PLAN-PLATFORM.md` is plan 3** (personal and team areas, folders, sharing with people, teams and links, registration, invitations, notifications, comments; phases P1 to P6) and wins over both where they differ. Read the plans
for the product and the document format, and change them only when the owner says so.

```bash

./scripts/redeploy.sh  (or .ps1)              # rebuild the image and start the local stack: web 3043, pgAdmin 3044, Postgres 3045; --clean / -Clean empties the volumes

./scripts/sync-matui.ps1 ; ./scripts/check-matui.ps1   # MatUi from MatDesign (the container of MatDesign on port 8060 serves /ui/matui.zip)

node tools/dt-icons.js                          # img/dt-icons.svg (designer and app icons, Lucide) from MatDesign's icon library; add a name to NAMES first

# browser checks (Playwright + installed Edge; see tests/e2e/README.md): a stack must run; from an empty database they make their own accounts
cd tests/e2e && npm install
node run-all.js http://localhost:3043           # engine, pwa, demo, home, templates, designer, canva, content, output, ai in sequence (~10 min); --only pwa,demo for a selection; --fake-host 127.0.0.1 for the AI check when the app runs by dotnet run

# the checks write tests/e2e/test-account.json for the database they ran on: back it up first and restore it, or the checks against 3043 lose their accounts
```

Local stack: `docker-compose.local.yml` (project `designthix-local`, fixed subnet `10.253.43.0/24` because Docker on a PC with many stacks runs out of address
pools). `docker-compose.dev.yml` (`:nightly`, `designthix-dev`) and `docker-compose.yml` (`:latest`, `designthix`) pull from `ghcr.io/real-ttx/designthix`.
No `${...}` variables and no `.env` in any compose file. Environment variables of the app: `DESIGNTHIX_PORT`, `DESIGNTHIX_DATA`, `DESIGNTHIX_TEST_DB`,
`DESIGNTHIX__Database__Host` (and `Port`, `Database`, `Username`, `Password`).

## Layout

  `Data/` (`Csv` read/write, `ValueFormat` = the number rules of the engine, `ColumnDefs`), `Documents/` (`DesignDocument` records, `DocumentValidator` parse + normalise,
  `Placeholders`, `FormatPresets`, `DesignPackage`), `Output/` (`OutputPlan`: rows to labels, sheets, cells, fit scale).

## Rules of the domain

- Roles (account): **Admin** (users, AI, settings, platform items) and **Member** ("Mitglied"; everybody else; there is no Designer/Viewer any more). What a person may do with content is the **access level** per item (`Access`): their own area (personal space = Manage),
  team membership (Owner/Admin/Editor = Manage, team Viewer = View) and shares. Whoever may only View is the old "viewer": looks, runs outputs, prints, downloads, copies. The first user (setup assistant) is an Admin and gets the demo list and job in the personal area. Page policies `Admin`, `SignedIn` in `Program.cs`; every logic method checks again. A plan-2 database is converted once at start-up by `Services/PlatformMigration` (setting `Platform.Migrated`; team "Gemeinsamer Bereich": Admin -> Owner, Designer -> Editor, Viewer -> Viewer); it is C# because the old role names are no value of the new enum.
- Database: tables and columns PascalCase, `Id` bigint, `CreateDate/CreateUserId/UpdateDate/UpdateUserId` filled by `DtDbContext`, `UpdateState` soft delete
  (0 deleted, 1 created, 2 updated), enums as text, `*Json` properties are `jsonb`, a key that acts as a secret is a separate `Token` (uuid).
- UI: CRUD = list page + create/edit page (delete on the edit page); every list has a toolbar above it, the pager directly below the table, list actions below;
  buttons in one row: Save, Back, space, Delete; pages with several areas use tabs; hide what does not apply (`data-show-if`).
- **No inline styles, no inline scripts, no event-handler attributes** (CSP `style-src 'self'; script-src 'self'`; images may be `data:`/`blob:`, fonts `data:`).
  Data values go to the DOM through the CSSOM (`el.style.setProperty`) or SVG attributes. **Never `innerHTML` with user data.** CSS classes of the app start with `dt-`.
- AI: one JSON object per answer (`LenientJson`), required field per action, at most two nudges then `Stuck`; limits before the call; tokens estimated (chars/4) when
  missing; changes go into `AiJournalEntry` and can be undone newest first. Secrets only in `{data}/secrets/ai` (`AiSecretStore`), never in the database or a page.
  Actions: **Test**, **DataImport**, **DataFill**, **TextSuggest** (see "AI actions" below).
- Library: an **asset key** is lower case (`^[a-z0-9][a-z0-9_-]{0,63}$`), unique among the records that are not deleted, and is what designs (`{ "asset": "flag-de" }`) and image cells of
  data lists hold; matching is case-insensitive. Uploads are sniffed by their bytes (never the name); an SVG goes through `SvgSafe` (cleaned: script, foreignObject, `on*`, external or
  `javascript:` references, unsafe `style`; refused: DTD/entities, > 2 MB, nesting > 100) and is stored in its cleaned form; `/media` adds a CSP (`default-src 'none'`) and `nosniff`.
  Built-ins (`builtin.json`, `fonts.json`, six sheet layouts) are seeded by `LibrarySeeder` and remembered by `BuiltInKey` (also when renamed or deleted softly), so a deleted built-in
  stays deleted. A soft delete lets go of the bytes. Fonts: `/fonts.css` has one `@font-face` per font (`font-display: block`, weight range for variable fonts); font and media addresses
  carry a hash and are immutable. The `fonts.css` link is only in the head of signed-in pages.
- Revisions: `Design.Revision` and `DataList.Revision` are concurrency tokens. A save carries the revision it started from; a stale one is a `RevisionConflictException` (HTTP 409 with the
  current `revision`). `POST /api/designs/{id}` validates and normalises the document with `DocumentValidator` (the engine's `normalize` is the reference; a test compares them), bumps
  the revision and writes a `DesignRevision` (the newest 30 stay). The data list grid saves ALL rows in one POST in their order (rows left out are deleted, `Position` = index).
  CSV export writes `;`, UTF-8 BOM, the column keys as header plus `_Kopien` and `_Aktiv` (no key can start with an underscore); the import maps each CSV column to a column, `@new`, `@copies`, `@active` or nothing.
- Accent (light blue, slightly green) `#1fb3d6`, dark text on it (`--mat-app-on-accent`), links `#0a7590`; the turquoise-to-blue gradient is only for logos.

## Start, navigation, templates (K5)

Breadcrumbs of the batch pages start with "Serien (Zusatz)". Admin menu unchanged. `ShellModel.Spaces/Teams/WritableSpaces` carry the areas.

  `/Designs/Create?format=<key>` (works without script) that `create.js` turns into `POST /api/designs` -> editor `/Designs/{id}/Designer`. A new format tile needs its proportions in `home.css` (attribute selectors on `data-format`; no inline styles).
- **Start page** (`Pages/Index`, `OwnHead`): heading, search (`?q=`, server-side, `DesignLogic.SearchAsync`: designs and templates by name, category, description; it passes an ILIKE escape character, the older list searches do not, so a `%` there is not literal),
  format tiles, row of templates (`FeaturedTemplatesAsync`: round robin over the categories), "Zuletzt verwendet" (the file browser in the mode "recent": what the person opened or made, `ItemVisit`; designs, data lists, jobs), key figures at the bottom.
  The search (`?q=`) shows the templates found and, in the browser mode "search", everything else the person may see (folders, designs without templates, lists, jobs, images; `ItemQuery.ExcludeTemplates`).
  Every member may "Vorlage verwenden" (a copy in their own area); "Bearbeiten" on a template only for an administrator (templates are platform items). Creating, copying and duplicating a design/list/job counts as using it (`ItemLogic.VisitAsync`).

  `Templates.Seeded` holds the JSON list of the slugs seeded, so a template added in a later version is added to an existing database once and a deleted one never comes back. The Käsetheke is not in that list: it is the demo (`kaesetheke.json`, schema 2).
  **The files are generated**: write the template in `tools/templates/NN-<slug>.js` (helpers in `tools/templates/dsl.js`: `text`, `rect`, `icon`, `frame`, `qr`, `barcode`, `group` ...), run `node tools/templates-build.js` (it normalises through the engine, so the file is already what
  `DocumentValidator` writes; a test compares) and LOOK at the result with `node tools/templates-preview.js --out <folder> [--rows] [--sheet 2] [--editor]` (Playwright + Edge, needs no app). Rules: only bundled fonts, built-in media keys, Lucide names that exist,
  no photos (an image without a source is a frame; put a tinted shape behind it so the thumbnail does not look empty), sizes readable at the physical size, font sizes in pt (in a px document 1 pt = 1.333 px), letter spacing in em.
- Tests: `Integration/TemplateTests` (files valid and already normalised, every font/medium/icon exists, seeding once / new one added / deleted stays deleted, search, recent, featured, roles), `tests/e2e/home-check.js`, `tests/e2e/templates-check.js` (every template draws without an engine warning).

## The designer

The editor of `/Designs/{id}/Designer` (`Pages/Designs/Designer.cshtml`, layout `_Designer`: no menu, no page scroll) is Canva-style: top bar (back, Datei menu, undo/redo, save state, name, Serie, Herunterladen, Drucken), an **icon rail** (Vorlagen, Elemente,
Text, Uploads, Marke, Ebenen, Daten (Zusatz)) with a wide **panel** (about 340 px, collapsible, context pages with a back arrow), a **contextual toolbar** above the canvas (no permanent properties panel), the canvas, and a bottom bar (page strip, zoom).
The `.cshtml` is only the frame; the scripts build everything with DOM APIs. **`docs/EDITOR.md` is the full description** (modules, state, events, how to extend, server contracts); this is what to keep in mind.
Scripts in `wwwroot/js`, loaded in this order after `dt-engine.js`, `ai.js` and `dt-media.js`:
`designer.core` (helpers, geometry, groups, **`D.createApp`: state and every command**) → `.canvas` (drawing, overlay, gestures, hit testing, snapping, zoom, inline text) → `.menu` (`D.menu`, `D.popover`, `D.dialog`) → `.ui` (form blocks) → `.colors`
(colour popover) → `.gradient` → `.commands` (`D.cmd`, `D.contextItems`) → `.toolbar-parts` → `.crop` → `.toolbar` → `.panels` (rail + panel framework, Marke) → `.icons-de` → `.panel-elements` → `.panel-text` → `.panel-templates` → `.panel-uploads`
→ `.panel-layers` → `.panel-data` → `.panel-position` → `.effects` (pages Effekte and Anpassen) → `.pages` (bottom bar) → `.io` (D.dnd, upload, paste, drop) → `.save` → `.file` (Datei menu, Größe ändern, Herunterladen) → `.shortcuts` → `designer.js` (boot).
Styles: `css/designer.css` + `css/dt-media.css`, MatUi tokens, flat (only menus, popovers and dialogs have a shadow).

How it behaves (keep these when changing it):
- **Changes**: `app.edit(mutator, {merge, render, structure})` is one undo step (a `merge` key coalesces typing and nudging for about a second). A gesture uses `app.tx().apply(...)`: the first change pushes ONE undo step. The document is changed
  live during a drag, but the engine is not run: a move only gives the node's `<g>` a transform (`render: 'none'`), a rotation sets its `rotate()`, a resize re-renders once per frame (`'soon'`); on release the engine draws again.
  Events (`app.on`): `doc {reason, render, structure}`, `selection`, `history`, `page`, `pages`, `preview`, `state`, `fonts`, `assets`, `brand`, `datalists`, `zoom`, `readonly`, `editing`, `warnings`, `rendered`, `dirty`, `uploaded`, `panel`,
  `contextmenu`, `node:dblclick`. `structure: true` rebuilds the layers and the panels, otherwise the controls only refresh (an input with focus is never overwritten).
- **Coordinates, groups**: the document unit everywhere; the overlay is in CSS pixels of the sheet (`app.scale()`). A **group** holds its children in *page coordinates*; its box is the union of the children (kept by `D.fixGroups` after every change), its rotation/flip
  apply around the centre of that box. A click selects the top-level node, a double click (or Ctrl+click) the child (`D.toFrame/toWorld` convert pointer and overlay). Find a node with `app.locate(id)` (`{ el, list, index, chain }`), `app.element(id)` for any page.
- **Toolbar** (`designer.toolbar.js`): kinds page, text, image, strip, shape, line, icon, qr, barcode, group, multi; built from `D.toolbar.register/extend`. `D.toolbar.setOverride(fn)` replaces the toolbar for a mode (crop mode) until `setOverride(null)`. When the controls do not fit the
  toolbar adds **`is-compact`** (words next to icons go; `dt-tb--keeptext` keeps them) and, when it is still too wide, **`is-tight`** (smaller minimum widths); a button always has an `aria-label` (the checks find buttons by it). An empty image frame offers "Bild wählen", an image "Ersetzen".
- **Colour picker** (`D.colors.open(anchor, { title, get, onChange(value, final), allowNone, allowGradient })`): sections in `D.colors.sections` (Dokumentfarben, Markenfarben, Standardfarben, native picker, hex field, pipette where `EyeDropper` exists) and, with `allowGradient`, the tabs in
  `D.colors.tabs` (Verlauf). A value is `'#rrggbb'`, `null` or a gradient. In a panel use `D.ui.colour({...})`.
- **Crop mode** (`D.crop.start(id)`, double click on an image, toolbar, context menu): only for an image whose source is an asset of the library. Works in the content frame of the element, writes nothing until Fertig/Enter (ONE undo step: the box becomes the window and `crop` the visible
  fraction), Escape throws everything away. `D.canvas.setModal` keeps the canvas from starting gestures meanwhile.
- **Drag and drop**: `D.dnd.attach(tile, { ghost, onClick, onDrop(x, y) })` (pointer events, capture at once) for the tiles of the panels; `D.canvas.dropAsset(asset, clientX, clientY)` puts an asset where it was dropped (onto an image, frame or strip slot it replaces the source).
  **Paste and drop of files** (`designer.io.js`): Ctrl+V with an image uploads it and inserts it, plain text becomes a text element, copied elements paste as elements (also into another design); files dropped from the explorer are uploaded and inserted at the drop point (several: cascaded),
  font files become fonts applied to the selected text. Errors and progress are German toasts. Uploads go through `POST /api/assets/upload` / `/api/fonts/upload` (several files per request).
- **Two format lists, do not mix them up**: `.dt-formats` (`css/home.css`, `_FormatTiles`) are the tiles of the start page and of the create dialog; `.dt-fmtlist` (`designer.css`, `designer.file.js`) is the radio list of "Größe ändern" in the editor.
- **Context menu** (`D.menu.open(items, {x, y} | {anchor})`): right click, long press on touch; entries come from `D.contextItems(node)` (element), `D.pageMenuItems()` (empty page), `D.pageThumbItems(i)` (page thumbnail); `{ label, icon, shortcut, run, disabled: true | 'reason', danger, checked, submenu, hidden }`.
  Keyboard navigable, Escape closes. The same builder serves Datei and the "⋯" menu.
- **Media browser** (`dt-media.js`, `window.DtMedia.pick(options, callback(key, asset))`): a MatUi dialog with tabs Uploads / Flaggen / Siegel / Logos / Alle, search, upload button, drop and paste; `options`: `title`, `tab`, `category`, `current`, **`allowNone`** (+ `noneLabel`: a button "Kein Bild",
  the callback gets `('', null)`). It is used everywhere an image is chosen: Ersetzen / Bild wählen, strip slot chips (never a dropdown), background image, the Uploads panel, field samples, `/Brand` logos, the cells of the data list grid and the image fields of the single print. Never write a second picker.
- **Autosave** (`designer.save.js`): 1.5 s after a change, on `visibilitychange`/`pagehide` (keepalive), Ctrl+S saves at once; no Save button. `POST /api/designs/{id}` carries `{ revision, document, autosave }`: **autosaves of one person within 10 minutes share one history entry** (`DesignLogic.AutosaveWindow`),
  Ctrl+S (`autosave: false`) makes a new `DesignRevision`; the newest 30 stay. 409 opens a dialog (Als Kopie speichern: `/copy`, then the new design opens; Neu laden). The draft is in `localStorage` `dt-draft-<id>` ({revision, document, time}, written 0.9 s after a change, removed after a save and on sign-out);
  the chosen preview list/row in `dt-preview-<id>`. Offline: the state says so, the save waits for `online`. After a save the thumbnail is rasterised (`maxWidth: 480`, sample values) and posted.
- **Herunterladen / Drucken** (`designer.file.js`): the dialog offers PNG, JPG, SVG (files; several pages become one ZIP) and PDF / Drucken (the print view); pages all/current/choice, size ×1 to ×4 or dpi, transparent background for PNG. Works without a data list (the sample values).
- **Panel Daten (Zusatz)**: fields, the preview with a data list and a row stepper (`D.data.choose(listId, index)`), the display condition of the selection, and the link "Serienausgabe erstellen". **Preview values**: `app.computeValues()` = the samples, over them the row of the chosen list; a field that is a column
  of the list takes the cell (empty = empty), a field without a column keeps its sample.
- **Hit testing** uses the geometry (rotation undone), topmost first, skips hidden, locked and not drawn nodes (a node the engine did not draw has no `<g data-el-id>`); an unfilled rectangle or ellipse only reacts on its outline. **Snapping**: page edges and centre, edges and centres of the other nodes, equal spacing
  (markers in the overlay); threshold 6 screen px (10 on touch), Alt switches it off, Alt+drag duplicates, Shift keeps the axis.
- **Sizes, phone, roles**: from 1024 px rail, panel and canvas side by side; 768 to 1023 px the panel is a drawer next to the rail; below 768 px the **phone editor**: the rail is the tab bar (Elemente, Text, Uploads, Ebenen, Mehr), the panel and the popovers are bottom sheets, the toolbar a scroller above the
  tab bar, handles have a 44 px hit area. A viewer (`canEdit=false`) gets the same page with `is-readonly` (everything visible, nothing editable; Herunterladen and Drucken work). Touch: `touch-action: none` on the canvas; one finger on a node drags it, on the page it pans, two fingers pinch and pan; a second tap on a text edits it.
- **Icons**: `D.icon(name)` takes `mat-i-*` from the toolkit sprite when it has the name, else `dt-i-*`; **icon elements** draw Lucide bodies from `lib/icons.json`, which the engine (`parseIconBody`) and `D.iconSvg` parse into plain `{ tag, attrs }` with an allowlist, never as HTML. Icon search: `D.iconSearch` folds umlauts
  and uses `D.iconWordsDe` (Lucide has no cheese or cow: German words map to the nearest icons). In Razor `Ui.Icon(...)` (toolkit) and `Ui.ToolIcon(...)` (app sprite).
- **Fonts**: the family select lists the `/api/fonts` families, each `<option>` in its own font through a class (`D.fontClass`, a rule inserted into an adopted style sheet: no inline style).
- Browser checks: `designer-check.js` (mechanics), `canva-check.js` (rail, panels, toolbar, context menu, paste/drop, media browser, pages, groups, autosave, 409, download, viewer, tablet, phone), `content-check.js` (elements, icons, text combinations, toolbar per kind, effects, crop, colour picker, brand, templates, resize,
  media browser everywhere; `--only elements,text,...`). Shared helpers in `tests/e2e/editor-lib.js`. `tests/e2e/demo-label.js` hands the demo document and rows of `Demo/kaesetheke.json` to the checks. Accounts: see `tests/e2e/README.md`.

## Output

The browser is the only renderer, so the server never draws a label: it hands the browser a **payload** and the browser renders it with `DtEngine` (the same code as the designer).
- **Entity / logic**: `OutputJob` (`Scale` fit|none, `StartPosition` 1-based first cell of the first sheet, `FileNamePattern`, `CropMarks`, `Dpi`, `RowSelection`,
  `SelectedRowIdsJson`, `Copies`, `Mode`, `Format`, `LastRunDate/UserId`). `OutputLogic` (static): `Query` (left joins: a deleted design/list/user is null, not a vanished row), `SaveAsync` (checks everything and
  drops what does not apply: no list = samples and selection All, PNG = single and no sheet fields, label count <= `OutputPlan.MaxLabels` 2000), `PayloadAsync`, `AdhocPayloadAsync`, `MarkRanAsync` (`ExecuteUpdate`, so a run is no
  change of the job), `LabelCountsAsync`. Designers write; every signed-in person reads, runs and uses the single print. The sums (rows to labels, sheets, cell of a label, fit scale) are `Core/Output/OutputPlan`; `output.js`
  and `outputs.js` repeat them for the live count and the placement (the tests keep both honest).
- **Payload** (`OutputLogic.OutputPayload`): the document, `labels` = `[{ rowId, copies, values }]` (copies = copies of the row x copies of the job, expanded by the script; values = the samples of the design with the cells of the
  list over them, for the fields the design uses), `sheet`, `fonts` (the faces of the families the texts use), `assets` (lower-case key to `/media/key?v=hash`, only keys the design and the rows use), `warnings` (missing media,
  fonts, columns, an empty selection). The page never trusts a key: an unknown one draws nothing and is listed.
- **Run page** (`Pages/Outputs/Run` for `/Outputs/{id}/Run`, `RunAdhoc` for `/Outputs/Run?design=&adhoc=token`, layout `_Print`, `js/output.js`): `data-state` (loading, rendering, ready, error), `data-labels`, `data-pages` for the checks.
  Print mode puts every label in mm on a page (`.dt-opage`; sizes and places are custom properties set with `style.setProperty`, which the CSP allows) and inserts the paper size as an `@page` rule into `output.css` through the
  CSSOM (`insertRule`; a `<style>` element would be blocked). Single: one page per label at the design size; sheet: cell by cell from the start position, a design larger than the cell is shrunk (`fit`) or left (`none`) and a warning
  says so, crop marks are one SVG path per sheet below the labels. Entries (rows) are drawn three at a time, copies are clones with new clip-path ids, results are put on the page **in label order**, the loop yields to the browser
  (message channel, a paint now and then). PNG mode: `rasterize` per row, `zip`, an object URL on `<a download>`, names from the pattern (`{Design}`, `{Nr}` padded to the width of the total, `{Kopie}`, field keys; characters a file
  system dislikes become `-`, trailing `-_. ` are cut). The run is noted after `window.print()` returned / `afterprint` / a click on the download.
- **Einzeldruck** (`/Designs/{id}/Print`, `outputs.js`): the form is made of the fields (image fields: key + the media browser `DtMedia.pick`), a live preview, copies, mode/sheet/start/crop/scale, DPI for PNG.
  "Drucken" / "PNG" keep the request in `sessionStorage` (`dt-adhoc-<token>`) and open `/Outputs/Run?design=&adhoc=token`, which posts it to `/api/outputs/adhoc`. Nothing is saved.
- **Export / import** (`Core/Documents/DesignPackage.cs` = `DesignPackageFormat` read/write/rewrite keys, `Logic/DesignPackageLogic`): `.dtx.json` = `{ format: "designthix-design", version: 1, name, category, description, document,
  assets: [{ key, name, category, contentType, base64 }], fonts: [{ family, weight, style, format, base64 }] }`, only the media the document uses and the fonts of those families that are not built in. Import (designers, <= 50 MB)
  checks like an upload (`DocumentValidator`, `AssetLogic.Prepare` = `FileSniffer` + `SvgSafe`, font sniffing) and refuses the whole file when one part is bad. A key that exists with the same content (hash of the cleaned or of the
  raw bytes) is reused, a key with other content comes in as `key-2`, `key-3` ... and the document is rewritten; a font is reused when the file is there, a face that exists with other content is not added (warning).
- Browser check: `node tests/e2e/output-check.js [base url] [--out folder]` (about 110 checks, screenshots to the temp folder, never into `docs/images`); shared helpers in `tests/e2e/lib.js` (also used by `designer-check.js`).

## AI actions

The AI layer (`AiLogic.RunAsync`, one JSON object per answer, limits before the call, nudges, steps, journal) has the DesignThix actions. **The boundary is in code**: the model proposes, `Core/Ai/AiOutputs.cs`
checks (pure functions, unit tested with hostile answers), the run stores the CHECKED proposal, the person applies it, the journal takes it back.
- **Files**: `Core/Ai/AiOutputs.cs` (`AiText.Clean/ForColumn`, `ImageAllowlist`, `DataImportCheck`, `DataFillCheck`, `TextSuggestCheck`), `Logic/AiLogic.cs` (run, limits, transport, undo, runs of a subject, "Weitermachen"),
  `Logic/AiDataLogic.cs` (import + fill: prepare, propose, proposal, apply, discard, revert), `Logic/AiTextLogic.cs` (text suggestions), `Logic/AiInstructions.cs` (the layers and the fixed part per action),
  `Endpoints/AiEndpoints.cs` (thin; policy `SignedIn`, the logic refuses a viewer with 403, antiforgery on every POST), `wwwroot/js/ai.js` + `css/ai.css` (all dialogs; model text only through `textContent`),
  `datalist.js` (the two grid buttons), `designer.props.js` (`aiSuggestButton`), `Services/Ai/AiTestSeam.cs`.
- **Instruction layers** (`AiInstructions.SystemText`): operator (config file) + operator addition per action, base instruction of the site (empty = built-in), **addition of the site per action** (`AiSettings.ActionInstructions`, edited on
  the settings page), the person's instruction for this step, the FIXED part (answer format, rules; nobody edits it), then the situation as the user message. `AiLogic.Compose/Show` build the text once: the run sends it and the
  endpoints `.../import/prompt`, `.../fill/prompt`, `.../suggest/prompt` return exactly it without calling the model ("Vollständige Anweisung anzeigen" in the dialogs); the run's first Message step stores it.
- **Flow of the data actions**: `ProposeImportAsync` / `ProposeFillAsync` -> `RunAsync` -> check -> `run.ResultJson` = the checked proposal (`kind` import|fill, columns, rows or values with old/new, warnings, notes, for fill the list `revision`),
  `run.Status = Waiting` (or Done when nothing is left) -> `GET /api/ai/runs/{id}/proposal` (own run, admin: any) -> `POST /api/ai/runs/{id}/apply` with only `include` (import: indexes of the proposed rows, fill: row ids) ->
  rows written from the STORED proposal, journal `AiJournalEntry(DataRow, id, "Zeile" | column key, old, new)`, list revision + 1, run Done. A fill is refused with `RevisionConflictException` (409) when the list changed since the proposal;
  an import only appends (capacity checked). `discard` ends a waiting proposal as Cancelled. The page never sends values to be written.
- **What the model sees** (decided by the code): import = columns (key, label, type), for every image column the allowed media (category of the column, else all; at most 300 keys + names), the pasted text (<= 60 000 chars) and the hint;
  fill = the target column, the rows of the SELECTION (<= 200, saved rows only) with only the context columns the person ticked (default: the text columns) and the current value; suggest = the text, the box size, field keys/labels/samples
  (<= 100, keys validated). A list with `ContainsPersonalData` is refused (`Call.Refusal`: the run is Cancelled with the reason, the model is not called, no data is written to the steps) unless `AiSettings.SendPersonalData`.
- **Validation rules** (`AiText`): a value is cleaned (script/`javascript:`/event handler/iframe/svg/style refused with a reason, other HTML tags stripped with a note, control + bidi + zero-width characters removed, line breaks only in
  multiline), length refused (not cut) above 500 (text), 2000 (multiline), 40 (number/price), 80 (image); number/price parse with `ValueFormat` (price written with its decimals), |n| <= 1e12; image only from the allowlist (written as the key is
  spelled); unknown keys dropped and named (a label is accepted as a key); <= 500 rows; fill: row ids must be among the selected ones, once each, empty answers change nothing; suggestions: <= 5, exactly the placeholders of the original
  (as a set, case-insensitive), no duplicates, not the original.
- **Roles**: level Edit on the list or design for every action (View only: no buttons, endpoints 403). Admin: settings, profiles, the run list/details (`/Admin/Ai/Runs`, with subject links), `Weitermachen`. A **designer sees their own runs**
  of a data list in the panel "Letzte KI-Läufe" (Import/Export tab: "Vorschlag ansehen", "Rückgängig"); an administrator sees all. Undo: own runs (admin: any), newest first (`NewerRunAsync`), a value changed by hand since is left alone and said so.
- **Limits** (`RunAsync`, before the call): per minute per address, per user per day (`UserDailyTokens`) and month (`UserMonthlyTokens`), all users per month, runs per address per day (daily hash). Tokens come from the provider or are
  estimated (chars / 4, `TokensEstimated`). `AiRun.RequestJson` keeps the request so `Weitermachen` (admin, details page) can run it again as a new run; a proposal of another person is opened through its link `...?aiRun=<id>` (own runs only).
- **Test seam**: `AiTestSeam` (singleton, registered only by `AppTests.AppFactory`): `Handler = (AiRequest, ct) => Task<AiResponse>` replaces the transport (profile/relay/network); `Requests` records what was sent. Tests reset it
  (`ResetAsync` in `Integration/AiTests.cs`: no brake, no budget) and set `AiSettings` through `SettingLogic.SaveAsync`. Production never registers it.
- **Browser check**: `node tests/e2e/ai-check.js [base] [--fake-host 127.0.0.1] [--fake-port 3066] [--out folder]` starts a fake OpenAI-compatible server (`/v1/models`, `/v1/chat/completions`, answers depend on the task named in the
  fixed part of the instruction) and configures it as a profile through the admin UI; the Docker app reaches it at `http://host.docker.internal:3066/v1` (verified); with `dotnet run` on 3053 pass `--fake-host 127.0.0.1`.
  It raises the address limits in the settings first (the check makes many calls) and restores them, and deletes its profile at the end.

## Review notes (what was checked, keep it so)

- **No `innerHTML`, `insertAdjacentHTML`, `outerHTML`, `eval`, `new Function`, `style=` in markup strings, `.style.cssText`** in any script of the app (MatUi uses them for its own markup with escaped text; the check scripts of `tests/e2e` may use `eval` inside the test page); model text only through `textContent`. Icon bodies are only ever parsed (`DOMParser` on an inert document) into an allowlist of tags and attributes with validated values and built with `createElementNS`.
- **Uploads** (`/api/assets/upload`, `/api/fonts/upload`, paste, drop): every member (`AssetLogic.RequireUploader`; the upload lands in the personal area or the folder given) and antiforgery before the body is read, at most 40 files and 120 MB per request, 12 MB per file, `FileSniffer` by bytes + `SvgSafe`, the key comes from the file name through `Slug` (a path or odd characters never reach it; a taken key gets `-2`, `-3`, also when two uploads race: the unique index decides and the loser asks again), a pasted image without a name is `bild-<yyyyMMdd-HHmmss>`.
- **CSP and headers** (`Program.cs` middleware) are on every answer, also static files, redirects, errors and the run/print pages; `/media` replaces the CSP of an SVG by `default-src 'none'`; `nosniff` everywhere.
- **Antiforgery**: Razor Pages check it themselves; every `MapPost` goes through `LibraryEndpoints.Guard` (token in the header `RequestVerificationToken`, from `<meta name="dt-csrf">`).
- **Permissions**: `Integration/AccessTests` is the matrix of the levels (own area, team roles, share on item/folder/team, link, system items, trash) against every kind; `Integration/PermissionTests` is a table of every logic method that writes and runs it as owner, View-only member, stranger (404) and administrator. A new write method goes into that table. `KeyGuessingTests`: an asset, font or thumbnail address is a capability (`?v=` / hash prefix) and nothing else leaks; `/media` without the hash needs a signed-in person who may see the asset (anonymous: 401, no access: 404), built-ins are `public`, the rest `private`.
- **Secrets** never in a page, a log or the database: API keys in `{data}/secrets/ai`, messages of the AI client are logged with the key replaced.
- `robots.txt`: `Disallow: /` but `Allow: /llms.txt` (the app is private); `llms.txt` follows llmstxt.org.

## Gotchas

- Plan 3 tests: derive from `Integration/PlatformTestBase` (fresh users per test instance, `Role.Admin|Member`, `AsAsync`); an HTTP test needs an administrator row in the database and `SetupState.Reset()` (else the app redirects to Setup). The AI limiter holds shared state: tests that call AI reset it (`AiTests.ResetAsync`). Rows that are sorted after projection must be records with `init` properties (also `SpaceRow`, `ItemRow`). A trashed item keeps its asset key until it is purged. An asset a design or list uses must be visible to the saver, or already be used by an item the saver may View (`AssetRefs.RequireUsableAsync`): a browser check that wants a "gone" image uploads one first (`uploadImage`) and removes it with `purgeImage`.

- AI: a model answer is read leniently (`LenientJson`: fences, chatter, trailing commas), so `GetRawText()` of the element is NOT valid JSON: store `JsonSerializer.Serialize(element)` (jsonb refuses trailing commas). The prompt text uses
  `AppendLine`, i.e. CRLF when the app runs on Windows (`dotnet run`), LF in the container: a fake model must normalise before matching. Browsers: a `mat-table` becomes cards below 720 px, so the preview tables of `ai.js` use their own
  `dt-ai-table` (scrolls sideways inside its frame). A toast cannot hold buttons: `DtAi.undoToast` appends one to the last `.mat-toast` (call it AFTER closing a dialog, toasts move into an open dialog).

- EF Core: a list that projects to a record with a positional constructor cannot be sorted afterwards (`LINQ expression ... could not be translated`): the row types (`AssetRow`, `FontRow`,
  `DesignRow`, `DataListRow`) are records with `init` properties, filled with an object initialiser. A search inside a `jsonb` column needs `FromSqlInterpolated(... "Col"::text ILIKE {pattern})`;
  the global soft-delete filter still applies to it.
- Razor: `asp-route-id="@Model.Id"` with a null id renders an empty route value, the link cannot be built and the form gets `action=""` (the post then reaches no handler and the page
  just renders again). On pages with an optional id leave `asp-route-id` out: the ambient route value is used. A page whose tabs post to different handlers calls `ModelState.Clear()` in
  the handlers that do not post `Input` (else the summary shows errors of another tab). A `<dt-buttons delete-url="@(cond ? null : ...)">` with null shows no delete button.
- Browser checks: `tests/e2e/test-account.json` holds the accounts of ONE database; a check that finds an empty database (setup page) replaces it, so back it up before a clean run on another database (3053) and restore it afterwards. Thumbnails and previews are drawn lazily (IntersectionObserver,
  `rootMargin: 200px`, clipped by the scrolling row of templates): a check never waits for ALL `[data-dt-preview]` (that costs the whole timeout), only for those whose centre is on the screen. Look up records through the API (`/api/templates`, `/api/datalists`) or `?q=`, never on the first page of a list.
- Browser checks: a switch (`dt-switch`) is clicked through its `.mat-switch` label (the track covers the checkbox). The local database holds an administrator with two-factor sign-in
  (the checks make `designer` and `viewer` members through the setup assistant and the user page: two members who share nothing; what the second one looks at the first one shares with `shareWith` of `tests/e2e/lib.js`; templates are edited by the admin only).
- A `perl -pi` that inserts German quotes must read its script as UTF-8 (`use utf8`), else the text is stored double encoded; shell heredocs with German text failed half way here:
  use the editor tools for source files.

- Designer: a `<select>` option cannot carry a font through an inline style, so each option gets a class (`dt-ff-N`) from `D.fontClass`. Playwright: after `app.select([...])` wait two frames before reading the overlay (it is drawn in `requestAnimationFrame`), and use
  `D.canvas.whenIdle()` after every change before reading the drawing. Browser logs a 409/403 of a deliberate request as a console error: the check filters exactly those.
- Designer: `pointerdown` on a dragged tile must `setPointerCapture` at once; capturing only after the first move loses a fast drag. A text edit must keep the focus when a panel button inserts a placeholder (`data-keep-edit` + `pointerdown`/`mousedown` preventDefault).
- Razor: a variable named `section` clashes with the directive; collection initialisers inside tag-helper attributes do not compile (use a variable).
- `@page` route templates: braces are doubled (`{{0,59}}`) but brackets are not. A literal `{{Name}}` in Razor text is fine.
- Forms with an explicit `action` need `asp-antiforgery="true"`; edit forms that post to other handlers need `asp-page-handler=""` on the form.
- MatUi caps `svg` at `max-width: 100%`. The icon names for `Ui.Icon(...)` must exist in `ui/matui-icons.svg` (a name that is not there draws nothing; `printer` is NOT one of them: write `dt:printer`; `Ui.Icon("dt:name")`, `icon="dt:name"` of the controls and the menu items take the icons of the app's own sprite); the app's own
  icons are `dt-i-*` in `img/dt-icons.svg` (`Ui.ToolIcon(...)`; `IconSprite` merges the file into the inline sprite, so its first `>` must be the one of the `<svg>` tag: the licence comment goes after it).
- PWA: `pwa-check.js` is the reference for what an installable app needs here (manifest + maskable icons, theme colours = `--mat-bg` for light and dark, `viewport-fit=cover` with the safe-area paddings of MatUi, 16 px fields on touch screens, offline copy + banner + clean reload). iOS standalone ignores `theme-color`; the status bar style stays `default`. A synthetic `submit` event on a Logout form clears the kept pages (a check must not do that by accident).
- The service worker precaches the logo files one by one, so a missing file does not stop the installation.
- The embedded browser of the Claude app cannot register service workers; test the PWA with Playwright and Edge.
- The MatDesign dev container on port 8060 may serve an older MatUi than the copy here; compare `wwwroot/ui/matui.manifest.json` before syncing.
- Output: Playwright's `page.pdf()` prints with the **print** media unless `page.emulateMedia({ media: 'screen' })` was called before (then the PDF is made with the screen CSS and has extra pages): reset with `media: null`.
  A PDF of the browser has plain objects, so a check counts `/Type /Page` and reads the `/MediaBox` (points; 1 mm = 72 / 25.4).
- Output: `@page` must be inserted through `CSSStyleSheet.insertRule` into a style sheet that came from a file (`css/output.css`); the CSP forbids a `<style>` element. A label is placed with `--dt-x/--dt-y/--dt-w/--dt-h`
  custom properties set by script. Labels are put into the DOM in label order, not in the order the engine finishes (the first `.dt-olabel` is label 1).
- Output: a field hidden by `data-show-if` has its inputs disabled and posts nothing, so the server gets the defaults (no `Dpi` = the design's, no `SheetLayoutId`); the logic ignores sheet fields for PNG anyway. A radio group inside a hidden
  dependent still has its checked value for the script, so the script reads `Input.Format` before it trusts `Input.Mode`.
- Fast browser checks without Docker: stop nothing, run `dotnet run --project src/DesignThix --no-launch-profile` with `DESIGNTHIX_PORT=3053`, `DESIGNTHIX_DATA=<temp folder>` and the `DESIGNTHIX__Database__*` variables of the local stack
  (Postgres on 3045); static files come from `wwwroot` of the source, so a script change needs no rebuild (a page change does: stop the app first, the build cannot overwrite a running `DesignThix.exe`).
