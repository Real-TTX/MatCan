# Browser checks (tests/e2e)

Real-browser checks with [Playwright](https://playwright.dev) and the installed **Microsoft Edge** (headless; falls back to Playwright's Chromium).
They are not part of `dotnet test`. A stack must be running (`./scripts/redeploy.ps1 -Clean` gives a clean one on <http://localhost:3043>; for a clean run without wiping the local stack see "A clean run" below).

```bash
cd tests/e2e
npm install            # once
node run-all.js [base url]          # all checks one after the other, one summary line each; exit code 0 = all green
```

`run-all.js http://localhost:3043 --only pwa,designer` runs a selection (`engine`, `pwa`, `demo`, `home`, `projects`, `templates`, `lint` (only by name: the quality lint of the templates, about 8 minutes), `designer`, `canva`, `content`, `output`, `share`, `comments`, `teams`, `ai`, `aidesign`, `catalogs`; the order of the full run), `--quiet` prints only failures, `--fake-host h` / `--fake-port p` go to the AI checks, `--data <data folder of the app>` / `--catalog-port p` to the check of the catalogues. A full run takes about twelve minutes.

A clean run (without `redeploy -Clean`, which wipes the local stack's database)

1. Back up `test-account.json` (the checks write it for the database they ran on), or better point `DT_ACCOUNT_FILE` at a file in the temp folder (`lib.js` and `screens.js` use it instead; needed when two runs go side by side).
2. Start the app from source on port 3053 against a NEW database of the local Postgres (it creates the database itself): `DESIGNTHIX_PORT=3053 DESIGNTHIX_DATA=<temp folder> DESIGNTHIX__Database__Host=localhost DESIGNTHIX__Database__Port=3045 DESIGNTHIX__Database__Database=designthix_k6_x DESIGNTHIX__Database__Username=designthix DESIGNTHIX__Database__Password=designthix dotnet run --project src/DesignThix --no-launch-profile --artifacts-path <temp folder>`.
3. `node screens.js http://localhost:3053 --fake-host 127.0.0.1`, then `node run-all.js http://localhost:3053 --fake-host 127.0.0.1` - twice: the checks clean up after themselves or use names of their own, so a second run on the same database is green too (a full pass takes about ten minutes; the comments check wants a minute between two runs, a second pass is far enough away). Pass `--fake-port` when 3066 is taken.
4. Stop the app, `DROP DATABASE designthix_k6_x WITH (FORCE)` (through `docker exec designthix-local-db-1 psql -U designthix -d postgres`), restore `test-account.json`.

Notes

- **Accounts.** The checks need an administrator and two members (there are no other roles any more: the "designer" works in an own area, the "viewer" sees only what the designer shares with them). On an empty database the setup assistant makes `admin@example.com`, who makes
  `designer@example.com` and `viewer@example.com`; the three are written to `test-account.json` (git-ignored; it holds the accounts of ONE database, a check on an empty database replaces it). With an existing database put the accounts into that file
  (an administrator with two-factor sign-in cannot be used). **`DT_ACCOUNT_FILE=<file>`** points `lib.js` and `screens.js` at another file: use it for every run that is not against the local stack, so `test-account.json` keeps the accounts of the local stack (`screens.js` makes the administrator `anna@example.com` on an empty database).
- **Brakes the checks run into.** The platform brakes people (30 comments, 120 searches for people, 10 notifications of one kind from one person to another in 10 minutes, registrations per client and per address, guesses of hashes by an address that is not signed in): a check that needs many of them reads the limit from the page or waits, it never raises it.
- **One source for the demo.** `demo-label.js` reads `src/DesignThix/Demo/kaesetheke.json`, the same file the app embeds and seeds into an empty database.
- **Console errors and CSP violations** (a `securitypolicyviolation` listener is installed in every page) are part of each result.
- **Screenshots** of the checks go to the temp folder, never to `docs/images` (only `screens.js` writes there).
- `lib.js` has the helpers all checks share (browser, sign-in, accounts, console watcher).

## The fake provider of the catalogues (`fake-catalogs.js`)

`const { startFakeCatalogs } = require('./fake-catalogs.js'); const fake = await startFakeCatalogs(3073);` (or `node fake-catalogs.js 3073`) is a small stock-photo API in the shape of the reference catalogue `src/DesignThix/Catalogs/Providers/ExampleCatalog.cs`: `/api/collections`, `/api/search` (the words are looked for in the title and the name of the collection; `collection`, `page`, `per_page`, `orientation`), `/api/items/{id}`, the pictures `/img/{id}.png` (thumbnails) and `/files/{id}.png`, `/__stats` and `/__reset` (what was asked). It holds 45 usable pictures and four that must never be offered (CC BY-NC, CC BY-ND, no licence, a thumbnail on another host); the words `limit` (429 with Retry-After), `down` (500) and `leer` (nothing) are special; the key of the search-only catalogue is `testkey-123`. The app finds it only through the two environment variables above (the example catalogues do not exist without them), the providers through their own (below). A clean run on port 3060 is started like this (bash cannot put a name with a dash in front of a command, so use `env`):

```bash
env DESIGNTHIX_PORT=3060 DESIGNTHIX_DATA=<temp> DESIGNTHIX__Database__Host=localhost ... "DESIGNTHIX__Catalogs__example-browse__BaseUrl=http://127.0.0.1:3073" "DESIGNTHIX__Catalogs__example-search__BaseUrl=http://127.0.0.1:3073" dotnet run --project src/DesignThix --no-launch-profile --artifacts-path <temp>
node catalogs-check.js http://localhost:3060 --data <temp>
```

### Iconify and Fontsource (`fake-icons.js`, plan 5 / C3)

The same server answers as Iconify (`/collections`, `/collection?prefix=`, `/search`, `/{prefix}.json?icons=`) and as Fontsource (`/v1/fonts`; the files below `/files/<id>@latest/latin-<weight>-<style>.woff2`: the app takes `<BaseUrl>/files` for them when its address is the operator's). The icon bodies in `fixtures/iconify.json` are REAL ones (mdi, tabler, ph and fa7-solid, fetched once from api.iconify.design with their set records; mdi gets 60 more circles so that a set has three pages); four sets that must never be offered (colours, share-alike, non-commercial, GPL) are in `/collections` too, and the word `leck` makes the search answer with their icons. The fonts are 12 usable families (named like real ones) and four that must never be offered; the bytes are bundled fonts. Words: `limit` (429), `down` (500). `DESIGNTHIX__Catalogs__iconify__BaseUrl` and `...googlefonts__BaseUrl` name the fake; the check `ai-design-check.js` (section `foto`) needs the pexels and iconify ones and `--catalog-port` (run-all passes it).

The check can be run again against the same app, but not within two minutes of itself when it stopped half way (a provider that answered 429 is left alone for the time it named; the "Testen" of the administrator ends the pause). Use `Host=127.0.0.1` for the database: with `localhost` the first connections of a fresh process now and then run into the 15 s timeout of the SSL negotiation on Docker for Windows.

## The fake model (`fake-ai.js`)

`const { fake, startFake } = require('./fake-ai.js'); await startFake(3066);` starts an OpenAI-compatible server (`/v1/models`, `/v1/chat/completions`). It answers the one-shot AI actions (Test, import, fill, text suggestions) and, since plan 4, the **design assistant** ("agent" mode, recognised by "ANTWORTFORMAT (technisch, immer einhalten)" in the system message).
`fake.mode` = `'ok' | 'unauthorized' | 'announce' | 'nostream'` (`nostream` answers `stream: true` with a 400, so the fall back to a plain call is tested); `fake.requests` = the bodies; `fake.agent.calls` = what the assistant was asked (message of the person, step, number of pictures); `fake.streamDelayMs` (20) is the pause between the pieces of a streamed answer, `fake.restDelayMs` (null = the same) the pause for the pieces behind the `message` (the actions): `ai-design-check.js` uses 220 / 4 ms, so the words of a message are seen growing and a run still takes only about half a minute.
The agent answers are deterministic and depend on the newest message of the person and the results of the tools that came back; a scenario is chosen by words in the message: `stopp-test` (answers after 30 s: test "Stopp"), `frage-test` (ends with a question: the run waits), `format-test` (never speaks the protocol: "Angehalten"), `limit-test` (never done: "Limit erreicht"), `fehler-test` (a failing tool, then the repair), `bereich-test` (a write outside the scope fails, then a write inside), `anhang-test`, `referenz-test`, `vorlagen-test` (quality pass: `search_templates` with the numbered sheet that the open editor draws and the fake model really receives as an image, `apply_template` with `whole`, the sample texts with digits replaced, `look`), `pruefung-test` (quality pass: writes a title and says done WITHOUT looking; the review of the loop sends it back with "Prüfung vor dem Abschluss", then it looks; the call record has `gate: true`), `uebersetze`, `serie`, `varianten`, `weiter`, and everything else = "plakat" (seven steps: read, background and title, subtitle with a thin rule and icon, details and QR, a change of the title, `look`, done; the canvas changes step by step). A design that is still called "Unbenannt …" (the situation says so) is named in the second step with `rename_design` ("<title> – Plakat"); a message with `ohne-name` leaves that out, so the safety net of the server (the name from the first message) can be seen. With a design that has no format yet it chooses the poster A3 first.
The check scripts for the assistant raise the limits in `/Admin/Ai` first (a run makes one call per step). Scenarios that write elements name the page (`p1`): a design with several pages needs it.
