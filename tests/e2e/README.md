# Browser checks (tests/e2e)

Real-browser checks with [Playwright](https://playwright.dev) and the installed **Microsoft Edge** (headless; falls back to Playwright's Chromium).
They are not part of `dotnet test`. A stack must be running (`./scripts/redeploy.ps1 -Clean` gives a clean one on <http://localhost:3043>; for a clean run without wiping the local stack see "A clean run" below).

```bash
cd tests/e2e
npm install            # once
node run-all.js [base url]          # all checks one after the other, one summary line each; exit code 0 = all green
```

`run-all.js http://localhost:3043 --only pwa,designer` runs a selection (`engine`, `pwa`, `demo`, `home`, `projects`, `templates`, `designer`, `canva`, `content`, `output`, `share`, `comments`, `teams`, `ai`, `aidesign`; the order of the full run), `--quiet` prints only failures, `--fake-host h` / `--fake-port p` go to the AI check. A full run takes about ten minutes.

A clean run (without `redeploy -Clean`, which wipes the local stack's database)

1. Back up `test-account.json` (the checks write it for the database they ran on), or better point `DT_ACCOUNT_FILE` at a file in the temp folder (`lib.js` and `screens.js` use it instead; needed when two runs go side by side).
2. Start the app from source on port 3053 against a NEW database of the local Postgres (it creates the database itself): `DESIGNTHIX_PORT=3053 DESIGNTHIX_DATA=<temp folder> DESIGNTHIX__Database__Host=localhost DESIGNTHIX__Database__Port=3045 DESIGNTHIX__Database__Database=designthix_k6_x DESIGNTHIX__Database__Username=designthix DESIGNTHIX__Database__Password=designthix dotnet run --project src/DesignThix --no-launch-profile --artifacts-path <temp folder>`.
3. `node screens.js http://localhost:3053 --fake-host 127.0.0.1`, then `node run-all.js http://localhost:3053 --fake-host 127.0.0.1` - twice: the checks clean up after themselves or use names of their own, so a second run on the same database is green too (a full pass takes about ten minutes; the comments check wants a minute between two runs, a second pass is far enough away). Pass `--fake-port` when 3066 is taken.
4. Stop the app, `DROP DATABASE designthix_k6_x WITH (FORCE)` (through `docker exec designthix-local-db-1 psql -U designthix -d postgres`), restore `test-account.json`.

Notes

- **Accounts.** The checks need an administrator and two members (there are no other roles any more: the "designer" works in an own area, the "viewer" sees only what the designer shares with them). On an empty database the setup assistant makes `admin@example.com`, who makes
  `designer@example.com` and `viewer@example.com`; the three are written to `test-account.json` (git-ignored; it holds the accounts of ONE database, a check on an empty database replaces it). With an existing database put the accounts into that file
  (an administrator with two-factor sign-in cannot be used). **`DT_ACCOUNT_FILE=<file>`** points `lib.js` and `screens.js` at another file: use it for every run that is not against the local stack, so `test-account.json` keeps the accounts of the local stack (`screens.js` makes the administrator `anna@example.com` on an empty database).
- **Brakes the checks run into.** The platform brakes people (30 comments, 120 searches for people, 10 notifications of one kind from one person to another in 10 minutes, registrations per client and per address, guesses of hashes by an address that is not signed in): a check that needs many of them reads the limit from the page or waits, it never raises it.
- **One source for the demo.** `demo-label.js` reads `src/DesignThix/Demo/kaesetheke.json`, the same file the app embeds and seeds into an empty database.
- **Console errors and CSP violations** (a `securitypolicyviolation` listener is installed in every page) are part of each result.
- **Screenshots** of the checks go to the temp folder, never to `docs/images` (only `screens.js` writes there).
- `lib.js` has the helpers all checks share (browser, sign-in, accounts, console watcher).

## The fake model (`fake-ai.js`)

`const { fake, startFake } = require('./fake-ai.js'); await startFake(3066);` starts an OpenAI-compatible server (`/v1/models`, `/v1/chat/completions`). It answers the one-shot AI actions (Test, import, fill, text suggestions) and, since plan 4, the **design assistant** ("agent" mode, recognised by "ANTWORTFORMAT (technisch, immer einhalten)" in the system message).
`fake.mode` = `'ok' | 'unauthorized' | 'announce' | 'nostream'` (`nostream` answers `stream: true` with a 400, so the fall back to a plain call is tested); `fake.requests` = the bodies; `fake.agent.calls` = what the assistant was asked (message of the person, step, number of pictures); `fake.streamDelayMs` (20) is the pause between the pieces of a streamed answer, `fake.restDelayMs` (null = the same) the pause for the pieces behind the `message` (the actions): `ai-design-check.js` uses 220 / 4 ms, so the words of a message are seen growing and a run still takes only about half a minute.
The agent answers are deterministic and depend on the newest message of the person and the results of the tools that came back; a scenario is chosen by words in the message: `stopp-test` (answers after 30 s: test "Stopp"), `frage-test` (ends with a question: the run waits), `format-test` (never speaks the protocol: "Angehalten"), `limit-test` (never done: "Limit erreicht"), `fehler-test` (a failing tool, then the repair), `bereich-test` (a write outside the scope fails, then a write inside), `anhang-test`, `referenz-test`, `uebersetze`, `serie`, `varianten`, `weiter`, and everything else = "plakat" (seven steps: read, background and title, subtitle and icon, details and QR, a change of the title, `look`, done; the canvas changes step by step). With a design that has no format yet it chooses the poster A3 first.
The check scripts for the assistant raise the limits in `/Admin/Ai` first (a run makes one call per step). Scenarios that write elements name the page (`p1`): a design with several pages needs it.
